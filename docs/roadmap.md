# GG 전체 웹 로드맵 — "모든 사이트가 되는 브라우저"

2026-07-19, 목표 재정의: 기준을 네이버 홈에서 **웹 전체**로 올린다.
[네이버 설계](naver-perfect-design.md)는 이 로드맵의 T2 마일스톤으로
편입되고, 그 문서의 "비범위"(로그인·광고·미디어)는 여기서 전부
범위 안이다.

## 완벽의 정의 (측정 가능하게)

"모든 사이트"는 증명 불가능한 목표라서, 단계별 대리 지표로 정의한다:

| 지표 | 현재 | T3 목표 | 최종 |
|---|---|---|---|
| 사이트 바스켓 "쓸만함" | 8/9 "읽을만함" | 20/20 | 100/100 (트래픽 상위 실사용) |
| 실사용 시나리오 | 0 | 검색·뉴스 읽기·쇼핑 탐색 | 로그인 세션·결제 직전까지·미디어 재생 |
| 표준 커버리지 | 측정 안 함 | WPT 부분집합 도입 | WPT 통과율 추적 |

"쓸만함" = 뜨고, 읽히고, 클릭·입력이 되고, 눈에 띄게 깨진 곳이 없다.
web-platform-tests(WPT)는 T3부터 부분집합을 CI에 편입해 "우리 감"이
아니라 표준 스위트로 커버리지를 잰다.

## 티어 구조 (누적 — 앞 티어가 뒤 티어의 전제)

### T1. 문서 웹 — 읽는 웹 ✅ 사실상 완료
정적 HTML/CSS 사이트(뉴스·위키·블로그·정부)가 제대로 뜬다.
파서, 캐스케이드, 블록/인라인/플렉스/테이블/그리드/float,
웹폰트(woff2), 이미지/SVG, 스크롤.
**잔여**: HTML5 오류 복구 완전판, quirks 모드, RTL/양방향,
overflow 내부 스크롤, transition/@keyframes, float 롱테일.

### T2. 앱 웹 — 돌아가는 웹 ◆ 진행 중 (네이버 설계가 이 티어)
번들 JS가 실제로 돌고 SPA가 부팅한다. gg-js(ES2020+웹 API 표면),
동적 주입 체인, ES 모듈, React 부팅 검증까지 완료.
**잔여**: 실사이트 실측 루프(로컬 라운드), 실행 성능(IC→JIT),
부분 무효화 완성(부분 레이아웃·리페인트), GC(긴 세션),
dynamic import(), Proxy/Reflect 실물, Symbol 실물.
**판정**: 네이버 설계 B·C·D 게이트 + 바스켓 20.

### T3. 세션 웹 — 나로 로그인되는 웹 (구 비범위 → 범위 편입)
- **쿠키 완전판**: HttpOnly/Secure/SameSite/Domain/Path/만료,
  디스크 영속화(프로필), 서드파티 쿠키 정책
- **보안 모델**: 오리진 개념 실물화, CORS(fetch/XHR 프리플라이트),
  CSP 최소 준수, mixed-content 차단 — *로그인을 지원하는 순간
  보안이 기능이 된다. 대충 하면 안 되는 티어.*
- **iframe**: 문서 격리(프레임별 DOM/JS 컨텍스트), postMessage 실물,
  sandbox 속성 — 로그인 위젯·결제·임베드의 전제
- **폼 완성**: POST 제출(본문 인코딩·multipart), 파일 업로드,
  autocomplete, 비밀번호 필드 마스킹
- **TLS 위생**: 인증서 검증 엄격화, HSTS
- **판정**: 실서비스 2곳에서 로그인 → 세션 유지 → 로그아웃 왕복
  (자격증명은 사용자 소유 계정, 자동화 아닌 수동 시나리오)

### T4. 미디어 웹 — 보고 듣는 웹
- **canvas 2D 실렌더**: 지금은 no-op 스텁 — 래스터라이저는 이미
  있으니 드로잉 명령을 실제 픽셀로 (차트·게임의 전제)
- **`<video>`/`<audio>`**: 디코드(크레이트: symphonia/av 계열 검토)
  + 프레임 합성 + 컨트롤 UI. DRM(EME)은 명시적 미지원 선언
  (넷플릭스류는 이 선에서 제외 — 라이선스 문제라 기술 밖)
- **WebGL**: 소프트웨어 GL 또는 wgpu 백엔드 검토 — 지도류의 전제.
  비용이 크므로 T4 말미에 측정 후 결정
- **판정**: 유튜브 임베드 재생, 차트 사이트(canvas) 렌더, 지도 타일 표시

### T5. 플랫폼 완성 — 웹이 OS인 웹
- **Web Worker**: gg-js 인스턴스 격리는 이미 있음(P4 에이전트 설계
  유산) — 스레드+메시지 채널로 실물화
- **Service Worker + Cache API**: 오프라인·PWA
- **WebAssembly**: 인터프리터부터 (wasmi 임베드 검토)
- **WebRTC/WebSocket**: WebSocket 먼저(채팅·실시간 피드), RTC는 최후
- **접근성 트리**: 스냅샷 API가 이미 있으니 확장 (AI 네이티브
  전략과 합류)
- **판정**: PWA 1개 오프라인 구동, WASM 데모 구동, 웹소켓 채팅 동작

### 상시 트랙 (티어와 무관하게 계속)
- **성능**: JS 실행(IC→JIT), 레이아웃 러스트 이식, 리페인트 부분화,
  시작 시간 — 각 티어의 D-게이트
- **안정성**: GC·메모리 상한, 크래시 0 유지, 퍼징(파서에 임의 입력)
- **측정**: 바스켓 확장(9→20→100), WPT 부분집합, 골든 렌더 회귀
- **광고/서드파티**: T2까지는 스킵이 설계였지만 전체 웹에서는
  "샌드박스 안에서 돌되 페이지를 못 죽인다"로 전환 (연료·격리·
  타임아웃 — 이미 있는 인프라의 정책 전환)

## 순서에 대한 원칙

1. **티어는 순서대로** — 세션 웹(T3)은 앱 웹(T2)이 실증되기 전엔
   무의미하고, 미디어(T4)는 세션 없이는 반쪽이다.
2. **T2 완주가 지금의 전부다** — 네이버 설계의 로컬 라운드가
   그 관문이고, 이건 코드가 아니라 실측 루프가 남은 상태.
3. **보안이 걸린 T3부터는 "대충 v1"을 하지 않는다** — 렌더링 근사는
   무해하지만 보안 근사는 유해하다. 쿠키/CORS/iframe은 스펙 준수
   우선, 완성 전까지 로그인 기능 자체를 꺼둔다(기본 비활성 플래그).
4. **T4 이후는 착수 전에 재측정** — WebGL·비디오·WASM은 각각
   수개월급. 바스켓 100이 실제로 그걸 요구하는지 데이터로 확인
   후 착수한다.

## 규모에 대한 정직한 주석

T1~T2는 "한 사람 + AI 페어"가 몇 달에 도달할 수 있는 영역이고
(실제로 그렇게 왔다), T3는 보안 검토 때문에, T4~T5는 물량 때문에
각각 그 이상이다. 크로미엄이 수천 인년인 이유가 대부분 T3~T5에
있다. 이 로드맵은 "언젠가 다 한다"의 선언이 아니라 **순서와 판정
기준을 미리 박아두는 것**이다 — 어느 티어에서 멈추더라도 그 티어까지는
"완벽"하게.

## 진행 기록

**라운드 2 (07-19 밤) — 티어 관통 1차:**
- **T3 착수**: 쿠키 속성 완전판(Domain/Path/Expires/Secure/HttpOnly/
  SameSite — 타 도메인 쿠키 설정 차단 포함), POST 폼 제출
  (urlencoded, 리다이렉트 시 GET 전환), fetch/XHR CORS 검사
  (ACAO — 3개 서비스 루프 전부). 잔여: iframe 격리, CSP,
  multipart/파일 업로드, 쿠키 영속화. **로그인 기능은 T3 완성
  전까지 계속 꺼둠(원칙)**
- **T4 착수**: canvas 2D 실렌더 v1 — 드로잉 호출을 VM이 기록,
  셸이 Rust 래스터라이저로 픽셀화해 대체 요소로 표시(fillRect/
  stroke/path/fillText/arc; 변환·drawImage·부분 arc는 잔여).
  video/audio/WebGL 미착수
- **T5 착수**: **WebSocket 실물**(RFC6455 — 핸드셰이크·마스킹·
  ping/pong·close, fetch식 위임 채널로 JS WebSocket API 완결,
  로컬 에코 서버 E2E). **Web Worker 실물**(같은 날 후속 —
  GgWorker: 워커마다 자기 VM, postMessage 문자열 브리지 양방향,
  워커 자체 이벤트 루프+fetch까지 서비스. E2E: 메인 전역이
  워커에서 undefined = 격리 증명. 갭: structured clone은 JSON
  문자열 근사, 워커 내 DOM 없음(스펙 일치)). Service Worker/
  WASM 미착수
